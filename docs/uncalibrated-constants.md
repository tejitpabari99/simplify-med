# Uncalibrated constants

This is the durable register of constants named in this codebase's PRDs as "reasoned, not measured/calibrated" — content owned by PRD 15 §4.3, this file created and maintained here per PRD 16 §4.1/§9 and PRD 17 §9's confirmed split.

| Constant | Value | Defined in | What it controls | Why this value | How it would be calibrated | Owner (PRD) |
|---|---|---|---|---|---|---|
| `_QUOTE_MIN_LENGTH` | `12` | `backend/care_plan/pipeline.py:132` | Bare character-length floor in the quote/field informativeness check — one of three ways a grounding quote (03) or a rendered field (04, reused verbatim) can pass the "carries clinical content" test | "A bare character-count floor alone would reject legitimately short evidence" — chosen so short digit-free, short-word-free text is rejected, without being the sole gate (PRD 03 §4.3/§9) | Run the check against a sample of real grounded quotes; measure false-accept rate (junk quotes ≥12 chars with no digit/long word) and false-reject rate (genuinely informative quotes under every threshold) | 03 |
| `_QUOTE_LONG_WORD_MIN_LENGTH` | `7` | `backend/care_plan/pipeline.py:133` | Companion threshold: a single word of this length or more passes the same check outright (e.g. "metoprolol," "discontinued") | Chosen so words like "warfarin" (8 chars) pass even though the whole quote is under `_QUOTE_MIN_LENGTH` (PRD 03 §4.3/§9) | Same protocol as `_QUOTE_MIN_LENGTH`, same corpus — the two constants were chosen together and should be recalibrated together | 03 |
| `_MAX_PII_TOKEN_DELTA` | `4` | `backend/care_plan/pipeline.py:891` | Word-token-edit-distance ceiling in the corrector's diff check — how large a change to a PII-eligible field is tolerated as a name/facility swap rather than rejected as a disguised rewrite | "Chosen to comfortably cover a full name plus title while staying well short of what a genuine sentence-level rewrite would produce," explicitly "not empirically derived" (PRD 05 §4.6/§9) | Run the corrector end-to-end against real notes; measure how often a legitimate PII swap exceeds 4 tokens (false reject) and how often a real content rewrite stays at or under 4 (false accept) — listed as a manual step in PRD 05 §8 | 05 |
| `GLOSSARY_CURATION_TIMEOUT_S` | `20` | `backend/utils/constants.py:108` (`Constants.Deadlines.GLOSSARY_CURATION_TIMEOUT_S`) | Safety-net timeout on `glossary_future.result(...)` — how long the deterministic pipeline close waits for background glossary curation before falling back to uncurated terms | Derived by arithmetic, not measurement: sized so `SINGLE_JOB_INTERNAL_DEADLINE_S` (270s) + this timeout (20s) stays 10s under `JOB_TIMEOUT_SECONDS_SINGLE` (300s) — "a reasoned default, not measured against real latency" (PRD 06 §4.3/§9) | Watch whether it ever fires under normal (non-pathological) load during the PRD 06 §8 end-to-end smoke test; if it does, the 270+20 budget itself needs revisiting, not just this number | 06 |

| `_UNIT_WORD_MAX_LENGTH` | `15` | `backend/care_plan/pipeline.py:562` | Regex bound on how many characters after a number the numeric-parity tokenizer captures as a "unit word" (`mg`, `mmol/L`, `mIU/mL`, etc.) | "Long enough for the longest realistic compound lab unit... short enough that it can't silently swallow the start of the next clinical word if a unit is missing" — "named and reasoned, not derived" (PRD 10 §4.2) | Run the numeric-parity check against real notes; look for a legitimate compound unit truncated at 15 chars, or a false unit-match that over-captured into the next word (PRD 10 §9 already names this as the tuning trigger) | 10 |

**Deliberately not seeded, with reasons** (so a future maintainer doesn't wonder if these were missed): `Constants.Llm.MAX_TOKENS_LONG_FORM` (65,536) and `MAX_TOKENS` (8,192) are Vertex/Gemini API ceilings, not guesses about content; `Constants.Uploads.MAX_TEXT_LENGTH` (500,000 chars) and `Constants.Limits.MAX_AGGREGATE_FILE_BYTES` (10 MB) are stated as enormous-headroom fail-fast bounds, not calibration targets; `Constants.Limits.TRUSTED_PROXY_HOPS` (1) is a topology fact about the current Cloud Run deployment, not a judgment call, and is documented to need changing if the topology changes; `Constants.Limits.RATE_LIMIT_PER_IP_PER_HOUR` (5), `JOB_TTL_HOURS` (1), `RATE_LIMIT_COUNTER_TTL_HOURS` (2), and `Constants.Uploads.MIN_MEANINGFUL_CONTENT_CHARS` (20) are ordinary product/abuse-prevention configuration that no PRD's prose treats as an open calibration question — they're PD-*shaped* in the abstract (nobody measured the "right" rate limit either), but including every product config number in a fidelity-and-safety register would dilute the artifact's actual purpose, which is surfacing tunables that affect what a patient sees in their care plan. The register's scope stays narrow — pipeline-fidelity and output-quality tunables only.

**Maintenance rule:** any future PRD that introduces or changes a numeric constant explicitly described as reasoned-not-measured adds or updates a row in this file as part of that PRD's own scope.
