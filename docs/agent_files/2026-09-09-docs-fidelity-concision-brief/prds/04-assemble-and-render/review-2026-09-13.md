## Findings

| Severity | File:line | Finding | Evidence | Suggested fix |
|---|---|---|---|---|
| Medium | `backend/care_plan/pipeline.py:340-343` and `:347-350` (`_log_thin_fields`) | Logs the actual rendered patient-facing clinical text (`why`/`description`/`diagnosis.details[].description`) via `%r` at WARNING level, e.g. `"assemble_and_render: thin %s.%s field (%r) -- ..."`. This is an inconsistency with the sibling grounding-step checks in the *same module*: `_verify_ledger`'s three drop-and-log paths (`pipeline.py:248-264`) and `_verify_assembly`'s own `source_fact_ids`/`summary_fact_ids` guards (`pipeline.py:373-399`) all log only ids/categories/counts, deliberately never the fact/quote text itself. `_log_thin_fields` breaks that established pattern and puts clinical content (medication reasons, diagnosis descriptions — PII-scrubbed of names but not of clinical detail) into whatever log sink `logger.warning` reaches (application logs, log aggregation, potentially longer-retention/broader-access than the job document itself). Verified by direct read of both functions; this is specified verbatim in PRD §4.4/TASKS.md Task 4, so it is a defect in the PRD's own design, not a deviation by the implementer. | Log only the field name, item index, and length (or a truncated/hashed form) instead of the raw value — matching `_verify_ledger`'s existing id/category-only logging convention in this same file. If the raw content is genuinely needed for prompt-quality review (the stated purpose), route it to a dedicated, access-controlled diagnostic channel rather than the general application logger. |
| Low (informational) | `backend/care_plan/pipeline.py:336-351` (`_log_thin_fields` call ordering in `_verify_assembly`) | `_log_thin_fields(model)` runs on the model *before* the `source_fact_ids` soundness filter, so a thin-field warning can be logged for an item that `_verify_assembly` goes on to drop entirely in the same call (unbacked item). Not a functional bug — the log is explicitly "observability only" and not gated on the item surviving — but a reader could be confused seeing a warning for content that never reached the patient. | No action required; optional: note in the docstring that a flagged field may belong to an item later dropped by the soundness check. |
